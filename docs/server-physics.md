# Серверная физика Likvi — часть Жердина Руслана

Реализован отдельный зачётный заезд, в котором сервер Node.js самостоятельно
вычисляет физику дрона, столкновения, прохождение колец, время и очки. Клиент
передаёт клавиши и отображает полученные состояния. Это рабочая основа этапа
27 октября — 9 ноября из паспорта; объединение с аккаунтами, матчмейкингом и
сетевым сервером команды остаётся совместной задачей со Степаном.

## Запуск и демонстрация

```sh
npm ci --legacy-peer-deps
npm run dev:full
```

Команда запускает физический сервер на `127.0.0.1:3003` и Vite на свободном
порту начиная с 3000. Открыть адрес, напечатанный Vite. Затем выбрать
«Открыть режимы» → «Запустить серверный заезд».

Можно запускать отдельно в двух терминалах:

```sh
npm run server
npm run dev
```

1. Дождаться серверного отсчёта 5 секунд. Q/E меняют газ, WASD — наклон,
   стрелки влево/вправо — курс. Газ для зависания около 36%.
2. Пройти пять колец по очереди. Время и очки приходят с сервера.
3. При успешном финише результат сохраняется в `server/data/results.json`
   и появляется в отдельной таблице «Серверные результаты» на главной странице.
4. При аварии результат не записывается. «Начать заново» / «Новая попытка»
   создаёт новую сессию с новым отсчётом.
5. Для демонстрации потери связи остановить отдельный процесс `npm run server`:
   браузер останавливает попытку и предлагает подключиться заново.

Локальные тренировки и испытание подвижных ворот сохранены. Их результаты
не попадают в серверную таблицу. Прежняя таблица теперь явно обозначена как
локальные тренировочные результаты. Серверные гостевые заезды пока не
заполняют турнирную сетку автоматически.

## Как устроено

```text
Клавиатура → пакет {seq, keys} → HTTP → серверный Rapier (60 Гц)
                                              ↓
                         контакты, вода, кольца, время, финиш
                                              ↓
                       снимок состояния → Three.js и интерфейс
                                              ↓
                      подтверждённый финиш → файл результатов
```

Сервер использует те же контроллер, массу, составные коллайдеры, силу тяги,
шаг 1/60 с, трение и CCD, что локальная физика. У каждой попытки свой мир Rapier.
Статический BVH строится один раз при старте сервера и используется для
уточнения контактов и проверки воды. Коллайдеры Rapier создаются в каждом мире.

`src/physics/arena.js` содержит общий генератор карты и описания коллизионных
деталей зданий, крыш, деревьев, камней и фонарей. Клиент отображает эти описания
через `CollisionParts`, сервер по ним строит геометрию. Контур реки тоже общий.
Карту, маршрут и параметры физики сервер никогда не принимает от клиента.

Частота отправки управления — до 20 запросов в секунду, одновременно выполняется
не более одного запроса. Короткое нажатие сохраняется до ближайшей отправки;
потеря фокуса очищает клавиши. Сервер применяет последнее управление на своём
фиксированном шаге. Координаты на клиенте интерполируются между снимками;
локальная симуляция в зачётном режиме приостановлена. Предсказание движения и
компенсация большого сетевого запаздывания пока не реализованы.

Начало отсчёта, время попытки и последовательность колец определяет сервер.
Пакет управления не запускает дополнительный физический шаг. Частые запросы
не ускоряют дрон или таймер. При паузе серверного цикла более 250 мс активная
попытка прекращается, чтобы не засчитывать результат при замедленной симуляции.

## Протокол для интеграции со Степаном

Базовый путь: `/api/physics`. Vite проксирует его на порт 3003; собственный
транспорт реализован через встроенный модуль HTTP Node.js. Новых npm-зависимостей
для сервера не добавлено.

| Метод и путь | Вход | Результат |
| --- | --- | --- |
| `GET /health` | — | Готовность, версия протокола и карты |
| `POST /session` | `{"protocol":1,"arenaVersion":"polytech-physics-v2"}` | Секретный токен попытки и начальное состояние |
| `POST /input` | `{"seq":1,"keys":["KeyQ","KeyW"]}` | Текущее серверное состояние |
| `DELETE /session` | — | Закрытие своей попытки |
| `GET /results` | — | До 100 сохранённых серверных результатов |

Для `/input` и удаления сессии требуется `Authorization: Bearer <token>`.
Токен создаётся из 32 случайных байт, хранится у клиента в памяти соединения,
не помещается в URL или localStorage. Это владение гостевой попыткой, а не
авторизация пользователя. `seq` — возрастающее целое число; повторные и старые
пакеты отклоняются с кодом 409. Допустимы только восемь клавиш управления;
лишние поля, в том числе координаты, время, очки и параметры мира, отклоняются.

Ответ содержит `tick`, `ack`, `status`, `countdown`, `raceElapsedMs`,
`activeRingIndex`, `position`, `quaternion`, скорости, управляющие значения,
`crashInfo`, `result`, `resultStored`, `storageError` и `abortReason`.
Состояния симуляции: `countdown`, `running`, `crashed`, `finished`, `aborted`.

Для твёрдого контакта `crashInfo` содержит `point` в мировых метрах, `normal`
от поверхности к дрону, `surface`, общую относительную скорость `speed` в км/ч
и скорость сближения `normalSpeed` в м/с. По этим данным клиент запускает
анимацию, частицы и декаль. Идентификатор визуального события привязан к попытке
на клиенте; повторные снимки не запускают эффект снова.
После финиша интерфейс ждёт `resultStored: true`, прежде чем объявить сохранение.
При ошибке записи показывается ошибка; результат не выдаётся за сохранённый.

Серверный модуль `createServerRace` не зависит от HTTP или React. Для включения
в основной сервер нужно создавать миры внутри его комнат и вызывать `step`
из серверного таймера. Входы игроков проходят `acceptInput`, наружу передаётся
`snapshot`. Транспорт можно заменить на WebSocket без переноса расчётов в браузер.
Тестовые параметры `raceOptions` доступны только коду сервера, через HTTP их
передать нельзя. В обычном запуске действуют стандартные карта, маршрут и отсчёт.

## Ограничения и жизненный цикл

- После 300 мс без новых данных сервер перестаёт применять удержание клавиш;
  спустя 2 секунды прекращает попытку и замораживает дрон. Газ до прекращения
  сохраняет своё последнее значение, как в обычном управлении.
- Не более 8 одновременно существующих сессий; забытые сессии удаляются через
  30 секунд без запросов. Клиент закрывает сессию при выходе, аварии или
  завершении сохранения. Запоздавшее создание после выхода тоже очищается.
- Лимит тела запроса — 2048 байт. Лимит команд — 60 в секунду с запасом на
  краткий всплеск до 120. Максимальная длительность попытки — 10 минут.
- Результаты записываются последовательно через временный файл и замену
  основного файла. Они сохраняются после перезапуска процесса; файл исключён
  из Git. Хранилище рассчитано на один процесс, без общей базы данных.
- Сервер по умолчанию слушает только loopback и проверяет Host/Origin.
  `PHYSICS_PORT` и `PHYSICS_RESULTS` задают порт отдельного запуска и файл.
  При смене порта нужно также настроить прокси Vite. Для внешнего размещения
  необходимы HTTPS-прокси, явные разрешённые адреса и аккаунты основного сервера.

Защищён именно источник результатов: изменение координат или таблицы очков
в браузере не изменяет сохранённый сервером заезд. Автоматическое управление
клавишами, атаки на хост сервера и защита аккаунтов этой реализацией не решаются.
Многопользовательские столкновения, серверное управление демонстрационными
воротами и интеграция с турнирными комнатами ещё не реализованы.

## Проверки

```sh
npm test
npm run lint
npm run build
```

В общей серии — 48 тестов (включая эффекты и крайние случаи физики).
Серверные проверки покрывают общую геометрию,
недопустимые пакеты, повторные команды, невозможность ускорять симуляцию частотой
запросов, обрыв связи, аварийную посадку, зависание сервера, очистку сессий,
ограничение частоты запросов и ошибки сетевого клиента.

Автопилот из `tests/helpers/autopilot.js` проходит все пять колец на полной карте
через разрешённые клавиши. Отдельный тест повторяет такой заезд через настоящий
HTTP-сервер, проверяет единственную запись результата и чтение после остановки
и повторного запуска сервера. Тестовые результаты пишутся во временный каталог
и не добавляются в пользовательскую таблицу.

Локальный комплект не требует одинакового расчёта траектории в двух браузерах:
источник состояния один — сервер. Условия детерминированности Rapier и ограничения
генерации исходных параметров описаны в [документации Rapier](https://rapier.rs/docs/user_guides/javascript/determinism/).
Транспорт использует [стандартный HTTP API Node.js](https://nodejs.org/api/http.html).
